# Задача — Запрет повторной загрузки одного видео

В Video Quality Analyzer реализовать проверку дубликатов при создании задания через `POST /api/jobs`.

## Требования

1. Перед созданием задания проверить, существует ли уже видео с таким URL у текущего пользователя.

2. Для YouTube сравнивать видео по идентификатору ролика, а не по строке URL. Например:
   - `https://www.youtube.com/watch?v=LIIOUrjAETU`
   - `https://youtu.be/LIIOUrjAETU`

   Это одно и то же видео.

3. Если видео уже существует у пользователя, вернуть HTTP `409 Conflict`:

```json
{
  "statusCode": 409,
  "error": "Conflict",
  "code": "VIDEO_ALREADY_EXISTS",
  "message": "Видео уже добавлено",
  "jobId": "existing-job-id"
}
```

4. Не создавать повторное задание и не ставить скачивание в BullMQ независимо от текущего статуса существующего задания (`QUEUED`, `DOWNLOADING`, `DOWNLOADED` и т. д.).

5. Проверять дубликаты только в рамках текущего пользователя. Видео другого пользователя не должно блокировать загрузку.

6. Учесть одновременные запросы: проверка должна быть защищена от гонки на уровне БД, а не только предварительным SELECT.

7. На Angular-фронте корректно обрабатывать `409`: показывать сообщение «Видео уже добавлено», без отображения общей ошибки сервера.

8. Не изменять существующие задания, анализы, профили и очереди.

## Проверка

- Первая загрузка создаёт задание.
- Повторная загрузка того же видео возвращает `409`.
- Разные форматы URL одного YouTube-видео распознаются как дубликат.
- Другой пользователь может добавить то же видео.

Не создавать большой набор тестов. Достаточно минимальных проверок перечисленных сценариев.

Изучи существующую структуру проекта и реализуй изменение без лишнего рефакторинга.
