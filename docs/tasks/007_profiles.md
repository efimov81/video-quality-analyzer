# Задача — Профили анализа, автоматический запуск и управление через Angular

Доработать существующий Video Quality Analyzer. Использовать текущую архитектуру NestJS, PostgreSQL, BullMQ и Angular. Не переписывать работающие механизмы.

## 1. Профили

Расширить существующую модель профилей:

- `code` — уникальный короткий идентификатор для API и внешних интеграций (`base`, `full`, `strict` и т. д.).
- `isDefault` — признак профиля по умолчанию.
- Сохранить существующие `id`, `name`, `description`, `version`, `isActive`, `criteria`.
- Разрешить произвольные коды профилей, без фиксированного enum.
- Только один активный профиль может быть профилем по умолчанию.
- Неактивный профиль нельзя назначить по умолчанию или использовать для нового анализа.
- Существующие профили должны остаться работоспособными после миграции.

Доработать `GET /api/profiles`, чтобы он возвращал `code` и `isDefault` вместе с существующими полями.

Предусмотреть поиск профиля по `code` для интеграций.

## 2. Автоматический анализ

Расширить создание задания `POST /api/jobs`:

```json
{
  "sourceUrl": "https://youtu.be/LIIOUrjAETU",
  "autoAnalyze": true,
  "profileCode": "full"
}
```

Правила:

- `autoAnalyze` по умолчанию `false` для обратной совместимости.
- Если `autoAnalyze=true`, но `profileCode` не указан, использовать профиль по умолчанию.
- Если нет активного профиля по умолчанию, вернуть понятную ошибку до создания задания.
- Если профиль указан явно, проверить его существование и активность.
- Выбранный профиль фиксировать при создании задания.
- После успешного скачивания автоматически создавать analysis run через существующую бизнес-логику.
- Анализ выполняется через существующую очередь BullMQ.
- Не создавать повторный активный анализ для той же пары видео и профиля.
- Обеспечить безопасное повторное выполнение перехода после сбоев или перезапуска worker.
- Ошибка анализа не должна менять статус успешно скачанного видео.
- Ручной `POST /api/analysis-runs` сохранить.

## 3. Angular — управление профилями

Добавить страницу «Профили анализа», доступную администратору.

Функциональность:

- Список профилей: название, код, описание, версия, активность, профиль по умолчанию.
- Создание и редактирование профиля.
- Редактирование существующих критериев анализа.
- Активация и деактивация.
- Назначение профиля по умолчанию.
- Отображение ошибок валидации.

Использовать существующие API и модель версионирования. Не создавать отдельную систему хранения критериев.

## 4. Angular — создание видео и массовый запуск анализа

### Добавление видео

В существующем интерфейсе добавления видео:

- Переключатель «Автоматически анализировать».
- Выбор активного профиля из списка.
- По умолчанию выбирать профиль с `isDefault=true`.
- При отключённом автоматическом анализе создавать обычное задание на скачивание.

### Массовый запуск анализа

Реализовать на существующей странице «Видео», без отдельной страницы запуска анализа.

- Добавить чекбоксы для выбора видео.
- Добавить «Выбрать все» для текущей страницы.
- Добавить общую панель действий над списком:
  - количество выбранных видео;
  - выбор одного активного профиля анализа;
  - кнопку «Запустить анализ»;
  - кнопку «Снять выделение».
- Разрешать постановку анализа только для видео со статусом `DOWNLOADED`.
- Не создавать отдельные кнопки анализа и селекторы профилей на каждой карточке видео.
- При массовом запуске использовать существующую бизнес-логику создания analysis run.
- Обрабатывать каждое видео независимо: ошибка одного не должна прерывать постановку остальных.
- Показывать итог: сколько анализов поставлено в очередь, сколько пропущено, сколько завершилось ошибкой.
- Не блокировать повторный анализ видео по другому профилю.
- Предотвращать повторный активный анализ одного видео по тому же профилю.

### Отображение результатов

- На странице «Видео» показывать информацию о наличии и состоянии анализов.
- Для каждого видео предусмотреть переход к списку его анализов или отчётам.
- Сохранять независимые статусы скачивания и анализа.
- Не создавать отдельную страницу только ради запуска анализа.
- Использовать существующие API и компоненты Angular.

### Ограничения

Не добавлять сложную систему пакетных заданий и отдельную очередь для массового запуска. Достаточно последовательно отправлять запросы через существующий API с ограничением параллелизма, чтобы не перегружать backend.

## 5. API для будущих интеграций

Профили должны быть доступны через существующий API, чтобы Telegram и другие внешние клиенты могли:

- Получить список доступных профилей.
- Узнать профиль по умолчанию.
- Передать `profileCode` при создании задания.
- Не хранить UUID профилей в коде интеграций.

Не реализовывать Telegram, MCP или другие интеграции в этой задаче.

## Ограничения

- Не переписывать существующий анализатор, очереди и систему авторизации.
- Сохранить версионность профилей и воспроизводимость отчётов.
- Не добавлять лишних абстракций и универсальных механизмов.
- Не создавать большой набор тестов. Достаточно минимальных проверок ключевых сценариев.
- Использовать существующие компоненты и стиль Angular-приложения.
