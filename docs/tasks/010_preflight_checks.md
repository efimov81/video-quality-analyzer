# Задача: Preflight-проверки видео до скачивания

## Цель

Добавить в существующий pipeline Video Quality Analyzer предварительную проверку YouTube-видео через `yt-dlp` без скачивания медиаконтента.

Не запускать скачивание и тяжёлый анализ, если видео заведомо не соответствует требованиям активного профиля.

## Проверки

1. **Длительность:** минимальная и максимальная продолжительность из текущей версии профиля. Если видео слишком короткое или длинное — отклонить.
2. **YouTube Shorts:** определять Shorts по доступным метаданным и признакам URL. Ссылки `/shorts/` отклонять сразу, если профиль запрещает Shorts. Обычный URL `watch?v=...` сам по себе не гарантирует, что видео не является Shorts.
3. **Разрешение:** проверить доступность форматов, соответствующих минимальному разрешению профиля. Не путать разрешение доступного формата с разрешением фактически скачанного файла.
4. **Доступность:** обработать удалённые, приватные, недоступные и ограниченные видео.
5. **Неизвестные метаданные:** не считать отсутствие информации доказательством соответствия требованиям.

Все ограничения брать из существующего версионированного профиля. Не добавлять жёстко заданные пороги в код.

## Pipeline

`Получение URL → Preflight → Решение → Скачивание → Анализ`

- `REJECTED`: обнаружено однозначное нарушение — не скачивать.
- `PASSED`: предварительные проверки пройдены — скачивать.
- `INCONCLUSIVE`: данных недостаточно — применить явно заданную политику обработки.
- `ERROR`: техническая ошибка получения метаданных — сохранять причину, не выдавать её за нарушение требований.

Сохранять результаты каждой проверки и причины отклонения в существующей модели результатов, по возможности переиспользуя текущие сущности и статусы.

## Telegram

При раннем отклонении сразу отправлять короткое понятное сообщение:

**❌ Видео отклонено до скачивания**

Причина: длительность 32:15, допустимый максимум 20:00.

Или:

**❌ Видео отклонено до скачивания**

Причина: YouTube Shorts запрещены текущим профилем.

Если найдено несколько нарушений, показывать все подтверждённые причины.

## Технические требования

- Переиспользовать установленный `yt-dlp`.
- Не скачивать видео и аудио на этапе Preflight.
- Не запускать FFmpeg для предварительных проверок.
- Не создавать тяжёлую задачу анализа при раннем отклонении.
- Сохранить совместимость с существующим API и Telegram.
- Предусмотреть повторные запросы и обработку ошибок YouTube.
- Не считать вертикальный формат сам по себе доказательством принадлежности к Shorts.
- Не дублировать проверки и пороги, уже реализованные в проекте.

## Тестирование

Добавить автоматические тесты для коротких, длинных, допустимых, недоступных видео и Shorts, включая случаи неполных метаданных.

Проверить, что при раннем отклонении загрузчик вообще не вызывается.

Выполнить сборку, существующие тесты и доступные интеграционные проверки.

Перед реализацией изучить текущую архитектуру, модели профилей, очередь задач и Telegram-уведомления. Вносить минимальные необходимые изменения.
