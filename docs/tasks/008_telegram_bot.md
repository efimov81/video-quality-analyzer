# Задача — Telegram-интеграция Video Quality Analyzer

Реализовать Telegram-бота для отправки YouTube-видео на автоматический анализ и получения результатов.

Использовать существующие NestJS, PostgreSQL, BullMQ, пользователей, external_identities, профили анализа и механизм автоматической постановки анализа.

## 1. Telegram-бот

- Работает через long polling, без webhook и публичного IP.
- Токен бота хранится в `TELEGRAM_BOT_TOKEN` в `.env`.
- Если токен не настроен, приложение продолжает работать без Telegram.
- Не создавать отдельную систему авторизации или пользовательские API-токены.
- Использовать существующие backend-сервисы, а не HTTP-запросы к собственному API.

## 2. Привязка пользователей в Angular

В существующей админке пользователей добавить управление Telegram-привязкой.

- Поле Telegram ID для каждого пользователя.
- Администратор может добавить, изменить и удалить привязку.
- Использовать существующую таблицу `external_identities` с `provider=telegram`.
- Один Telegram ID может быть привязан только к одному пользователю.
- Показывать текущую привязку в карточке пользователя.
- Не менять существующий механизм авторизации веб-приложения.

## 3. Авторизация Telegram

При получении сообщения определять пользователя по Telegram `from.id`.

- `/start` и `/id` доступны всем.
- `/id` возвращает числовой Telegram ID отправителя.
- Если пользователь не привязан, остальные команды недоступны.
- Если пользователь заблокирован или неактивен в системе, доступ запрещён.
- Все задания создаются от имени привязанного пользователя с `source=telegram`.
- Нельзя передавать произвольный `userId` через команды Telegram.

## 4. Команды

`/start` — приветствие, краткая инструкция, информация о привязке.

`/id` — показать свой Telegram ID.

`/help` — список команд и примеры использования.

`/profiles` — список активных профилей с кодами и отметкой профиля по умолчанию.

`/analyze <url>` — скачать и проанализировать видео по профилю по умолчанию.

`/analyze <profileCode> <url>` — скачать и проанализировать видео по указанному профилю.

`/lang <en|ru>` — установить язык ответов бота.

Требования:

- Поддерживать русский (`ru`) и английский (`en`).
- При первом обращении определять язык по `language_code` пользователя Telegram: `ru` → русский, остальные → английский.
- Выбранный через `/lang` язык сохранять в БД и использовать при последующих обращениях.
- Настройка должна сохраняться после перезапуска бота.
- `/lang` без аргументов показывает текущий язык и доступные варианты.
- Команда доступна даже непривязанным пользователям.
- Локализовать все сообщения бота: приветствие, справку, список профилей, подтверждение задания, ошибки, статусы и уведомления о завершении анализа.
- Не переводить названия профилей, их `code`, названия видео и технические данные отчёта.
- Не добавлять отдельную библиотеку i18n ради двух языков. Достаточно простого словаря сообщений.
- Не менять язык веб-интерфейса.


Обычное сообщение, содержащее только YouTube URL, также должно запускать анализ по профилю по умолчанию.

Если профиль не существует, неактивен или отсутствует профиль по умолчанию — вернуть понятное сообщение без создания задания.

## 5. Создание задания

- Использовать существующий механизм создания jobs с `autoAnalyze=true`.
- Не дублировать логику скачивания и анализа.
- Сохранять `chatId` и `messageId` исходного сообщения для последующего уведомления.
- Сразу подтверждать приём ссылки, указывая выбранный профиль.
- Если видео уже существует (`VIDEO_ALREADY_EXISTS`), сообщать об этом и не создавать новое задание.
- Не обходить существующие ограничения доступа и дедупликации.

## 6. Уведомления о результатах

После завершения анализа отправлять в Telegram **новое сообщение**, а не редактировать старое.

Сообщение должно быть ответом на исходное сообщение пользователя через `reply_to_message_id`.

Включать:
- Название видео и ссылку.
- Использованный профиль и его версию.
- Общий результат анализа.
- Краткую сводку по проверкам.
- Доступ к полному отчёту с таймкодами.

Полный отчёт можно отправлять текстовым файлом или документом, если он слишком большой для сообщения Telegram.

При ошибке скачивания или анализа также отправлять новое сообщение с понятным описанием ошибки.

Уведомления должны быть устойчивы к перезапуску приложения: сохранять необходимые данные в БД, не полагаться только на события в памяти.

Не отправлять повторные уведомления при повторной обработке завершённой задачи.

## 7. Ограничения

- Не реализовывать Telegram Mini App, inline-кнопки, webhook и сложные меню.
- Не создавать отдельный микросервис для бота.
- Не переписывать существующие очереди и анализатор.
- Не менять структуру профилей.
- Не добавлять новые способы регистрации пользователей.
- Не создавать большой набор тестов — только минимальные проверки основных сценариев.
- Обновить `.env.example` и README с инструкцией запуска бота.

Сначала изучить существующую архитектуру и максимально переиспользовать готовые механизмы.
