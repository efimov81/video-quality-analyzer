# Задача: читаемая сводка анализа видео в Telegram

## Цель

Сейчас Telegram-бот после анализа видео отправляет результат и прикрепляет файл с подробным техническим отчётом.

Нужно расширить текст сообщения, добавив короткую, наглядную и понятную человеку сводку всех выполненных проверок.

**Существующий файл отчёта сохранить без изменений.** Новая сводка должна дополнять его, а не заменять.

## 1. Формат Telegram-сообщения

Пример желаемого результата (данные условные):

**🎬 Анализ видео завершён**

Название: Example Video  
Длительность: 12:34  
Разрешение: 1920×1080

**📊 Результаты проверок**

✅ Разрешение — соответствует требованиям  
✅ Звуковая дорожка — присутствует  
❌ Тишина — 2 проблемных интервала  
⚠️ Склейки — 18 переходов, 4 коротких  
✅ Чёрные экраны — не обнаружены  
✅ Зависания — не обнаружены  
⚠️ Резкость — недостаточно данных для оценки

**📍 Подозрительные участки**

🔴 02:14–02:22 — тишина, 8 секунд  
🟡 05:31 — короткий интервал между склейками  
🟡 08:12 — возможное зависание изображения

**Итого:** ✅ 4 | ❌ 1 | ⚠️ 2

📎 Подробный технический отчёт прикреплён.

Пример иллюстрирует формат, а не обязательные значения или результаты.

## 2. Требования к сводке

- Отображать все существующие проверки из результатов анализа.
- Использовать понятные русские названия вместо технических идентификаторов.
- `PASS` → ✅
- `FAIL` → ❌
- `WARNING` → ⚠️
- `ERROR` → ⚠️ с указанием ошибки выполнения.
- `SKIPPED` → ➖ с указанием, что проверка пропущена или отключена.
- Не смешивать отсутствие реализации с обнаруженным дефектом видео.
- Для каждой проверки выводить короткое описание результата, а при наличии — измеренное значение и порог.
- Не выводить большие JSON-объекты, диагностические дампы и технические подробности в сообщение.
- Если подробных данных нет, не придумывать их.
- Не изменять существующие статусы проверок или логику итогового вердикта.

Сводка должна формироваться из уже сохранённых результатов анализа.

## 3. Таймкоды

Если проверка содержит интервалы или временные метки нарушений, показывать их в отдельном разделе.

Для YouTube формировать кликабельные ссылки на соответствующий момент:

`https://www.youtube.com/watch?v=VIDEO_ID&t=134s`

Требования:

- Использовать реальные таймкоды из результатов анализатора.
- Не вычислять приблизительные интервалы из агрегированных значений.
- Для интервала показывать начало и конец.
- Для одиночного события показывать его время.
- Для видео без доступной ссылки выводить обычные таймкоды.
- Если событий много, показывать первые 5–10 наиболее значимых и количество оставшихся.
- Если временных меток нет, не выводить пустой раздел.
- Соблюдать ограничения длины Telegram-сообщений и корректно экранировать HTML/Markdown в зависимости от используемого parse mode.

## 4. Архитектура

Перед изменениями изучить существующую реализацию Telegram-бота, структуру результатов анализа и генерацию текущего отчёта.

Желательно выделить отдельный formatter/service, отвечающий за представление результатов в Telegram.

Не дублировать алгоритмы анализа и не добавлять новые обращения к FFmpeg.

Не изменять структуру БД и API без реальной необходимости.

Сохранить существующее поведение очереди, обработки ссылок, отправки сообщений и файлов.

Использовать существующую локализацию, если она предусмотрена в проекте. Не ломать поддержку других языков.

## 5. Проверки

Добавить тесты форматирования как минимум для следующих случаев:

- Все проверки прошли.
- Есть `FAIL` и `WARNING`.
- Есть `ERROR` и `SKIPPED`.
- Проверка не реализована или недостаточно данных.
- Есть несколько интервалов с таймкодами.
- Очень много событий — сообщение не превышает лимиты Telegram.
- Нет временных меток.
- Видео не с YouTube.
- Название видео содержит специальные символы разметки.

Проверить, что существующий подробный файл отчёта продолжает отправляться.

## 6. Ограничения

**Не делать:**

- Новые детекторы.
- Изменение порогов анализа.
- Изменение логики `ACCEPT` / `REJECT` / `MANUAL_REVIEW`.
- Новые таблицы БД.
- Переделку Telegram-бота или очередей.
- Новый интерфейс администратора.
- RAG, LLM или дополнительные внешние сервисы.

## Ожидаемый результат

После отправки ссылки пользователь получает понятный Telegram-отчёт, в котором за несколько секунд можно увидеть, какие технические проверки прошли, какие обнаружили нарушения и где находятся подозрительные участки.

Подробный файл отчёта остаётся доступным для изучения.

Реализуй задачу самостоятельно, используя существующую архитектуру проекта. Запусти доступные тесты и сборку. В конце кратко перечисли изменённые файлы, результаты проверок и ограничения реализации.
