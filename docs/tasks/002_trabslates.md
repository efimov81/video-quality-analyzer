# Задача: локализация Video Quality Analyzer (EN/RU)

## Цель

Реализовать полноценную локализацию приложения на английский и русский языки.

- Язык по умолчанию — **English (en)**.
- Пользователь может переключать язык на лету, без перезагрузки страницы.
- Выбранный язык сохраняется в `localStorage`.
- Язык не добавляется в URL.
- Использовать готовую библиотеку **Transloco (`@jsverse/transloco`)**.
- Переводы хранить в JSON-файлах.
- Не реализовывать собственный движок локализации.

Локализовать не только статический интерфейс, но и сообщения результатов анализа, которые сейчас формируются на backend на русском языке.

## 1. Backend — стабильные ключи сообщений

Проверить все анализаторы и формирование отчёта `GET /api/analysis-runs/{id}/report`.

Сейчас проверки возвращают поля вроде:

```json
{
  "checkType": "resolution",
  "status": "PASS",
  "details": "Разрешение и длительность соответствуют профилю."
}
```

Добавить структурированные поля:

```json
{
  "checkType": "resolution",
  "status": "PASS",
  "messageCode": "analysis.resolution.pass",
  "messageParams": {},
  "details": "Разрешение и длительность соответствуют профилю."
}
```

Требования:

1. Для всех типов проверок (`resolution`, `audio_presence`, `audio_silence`, `audio_loudness`, `background_noise`, `speech_vad`, `audio_clipping`, `scene_cuts`, `visual_brightness`, `blur`, `black_screens`, `frozen_frames`, `upscaling_experimental`) определить стабильные коды сообщений.
2. Коды должны отражать конкретный результат или причину, а не только `PASS`, `WARNING` или `FAIL`.
3. Для динамических сообщений использовать `messageParams`, например количество обнаруженных переходов, порог, измеренное значение и т. д.
4. Не передавать локализованные строки в `messageParams`, если их можно заменить кодами или числовыми значениями.
5. Сохранить `details` для обратной совместимости.
6. Не менять алгоритмы анализа, вычисление метрик, пороги и итоговые статусы.
7. Сохранить совместимость с уже записанными результатами анализа. Продумать хранение новых полей и обработку старых записей без `messageCode`.
8. Не переводить сообщения на backend: backend возвращает коды и параметры, frontend отвечает за язык.
9. Обновить DTO и OpenAPI-контракт, обеспечив строгую типизацию новых полей.

Не ограничиваться только `details`: проверить другие пользовательские сообщения, возвращаемые API, включая ошибки и пояснения в evidence. Если они требуют локализации, предусмотреть для них аналогичные структурированные коды и параметры.

## 2. Frontend — Transloco

Установить и настроить `@jsverse/transloco` в существующем standalone Angular-приложении.

Создать файлы переводов:

```text
src/assets/i18n/en.json
src/assets/i18n/ru.json
```

Если текущая конфигурация Angular использует другой каталог статических ресурсов, адаптировать пути к существующей структуре проекта.

Настроить:

- `en` — язык по умолчанию и fallback.
- `ru` — дополнительный язык.
- Загрузка переводов из JSON.
- Смена языка без перезагрузки.
- Сохранение выбора в `localStorage`.
- Восстановление сохранённого языка при запуске.
- Корректная работа при отсутствии или недоступности `localStorage`.

Не использовать локализацию через отдельные сборки Angular и не добавлять языковой префикс в маршруты.

## 3. Переключатель языка

Добавить в верхнюю часть интерфейса компактный переключатель:

`EN | RU`

Текущий язык должен быть визуально выделен.

При переключении должны сразу обновляться все переведённые элементы, включая уже открытые отчёты, без повторного запуска анализа и без повторной загрузки отчёта.

## 4. Локализация интерфейса

Перевести все пользовательские тексты в существующих компонентах:

- `AppComponent`
- `VideoCardComponent`
- `AnalysisReportComponent`

Включая:

- заголовки и описания;
- поля формы, кнопки, ошибки и состояния загрузки;
- статусы загрузок и анализов;
- историю анализов;
- названия проверок;
- общий вердикт `ACCEPT / REJECT`;
- заголовки `Measured values`, `Expected values`, `Evidence`;
- сообщения проверок и пояснения;
- даты и форматирование чисел с учётом выбранной локали, где это уместно.

Сами технические идентификаторы, названия кодеков, пути к файлам и ключи JSON не переводить.

## 5. Отчёты анализа

Использовать `messageCode` и `messageParams` из backend для получения локализованного сообщения через Transloco.

Например:

```json
// en.json
{
  "analysis": {
    "resolution": {
      "pass": "Resolution and duration meet the profile requirements."
    }
  }
}
```

```json
// ru.json
{
  "analysis": {
    "resolution": {
      "pass": "Разрешение и длительность соответствуют требованиям профиля."
    }
  }
}
```

Для динамических значений использовать интерполяцию Transloco.

Обеспечить локализацию всех реально существующих вариантов сообщений анализаторов, а не только примеров выше.

Для старых отчётов без `messageCode` предусмотреть безопасный fallback на `details`. Не пытаться автоматически переводить произвольный текст.

Если код перевода неизвестен, интерфейс не должен показывать пустое сообщение или необработанный ключ без понятного fallback.

## 6. OpenAPI и генерация клиента

После изменений backend:

1. Обновить Swagger DTO.
2. Перегенерировать Angular API-клиент через существующую команду `pnpm generate:api`.
3. Использовать сгенерированные типы.
4. Не редактировать generated-файлы вручную.
5. Не ослаблять строгие настройки TypeScript.

## 7. Проверки

Проверить:

- Первый запуск без сохранённого языка — английский.
- Переключение EN → RU → EN.
- Сохранение языка после перезагрузки.
- Переключение языка при открытом отчёте.
- Перевод всех статусов и типов проверок.
- Сообщения с динамическими параметрами.
- Старые результаты анализа без новых полей.
- Отсутствующие ключи перевода.
- Корректность OpenAPI и генерации клиента.

Запустить существующие `pnpm build`, `pnpm typecheck`, `pnpm test`.

## Ограничения

- Не менять бизнес-логику анализа.
- Не менять структуру приложения без необходимости.
- Не добавлять язык в URL.
- Не делать отдельные сборки для каждого языка.
- Не внедрять собственную систему переводов.
- Не переписывать интерфейс и стили без необходимости.

**Результат:** приложение полностью работает на EN/RU, включая технические отчёты, а backend возвращает независимые от языка структурированные сообщения.
