# Frontend workspace instructions

Используй Angular и TypeScript.
Следуй актуальным официальным рекомендациям Angular для standalone components и routing.
UI общается с backend через REST API.
Не дублируй бизнес-логику backend на клиенте.
Состояние и абстракции добавляй по реальной необходимости, избегай преждевременной сложности.

## Компоненты и структура

- Используй standalone-компоненты и `ChangeDetectionStrategy.OnPush`.
- Храни TypeScript и HTML каждого компонента в отдельных `.ts` и `.html` файлах. Добавляй `.css`, только если компоненту нужны собственные стили.
- Не используй inline templates и большие inline styles.
- Группируй UI по feature в `src/app/features/<feature>/`; общие сервисы и модели размещай в `src/app/core/`.
- Используй Angular control flow (`@if`, `@for`, `@switch`) и держи каждый компонент сфокусированным на одной задаче.
- Сохраняй существующее поведение и Tailwind CSS 4 как основной способ оформления; не добавляй UI-фреймворки без обоснованной необходимости.

## Состояние и асинхронные операции

- Используй Signals для изменяемого состояния интерфейса, `computed()` — для производных значений. Не храни отдельно значения, которые можно вычислить из другого состояния.
- Используй `effect()` только для настоящих побочных эффектов.
- Пользовательские настройки храни в core preferences service на Signals; компоненты не должны обращаться к `localStorage` напрямую.
- Для размера текста используй семантические Tailwind utilities и центральные theme tokens, а не фиксированные pixel font sizes.
- Используй Angular `HttpClient` и RxJS для запросов. Для отображения Observable применяй `toSignal()` или `async` pipe; для вручную управляемых подписок используй `takeUntilDestroyed()`.
- Поддерживай zoneless change detection Angular 21: обновляй состояние через Signals, читаемые шаблоном. Не используй `ChangeDetectorRef.detectChanges()` или `markForCheck()` как обход проблем обновления состояния.

## Формы и контракты

- Используй `ReactiveFormsModule`, типизированные формы и Angular validators для форм приложения.
- Не управляй полями формы через набор независимых строковых свойств и обработчиков событий.
- Держи HTTP-вызовы в API-сервисах, а типы и интерфейсы — в отдельных model-файлах. Не дублируй API-контракты и серверную бизнес-логику в компонентах.
- Используй сгенерированные из OpenAPI DTO и API-сервисы из `src/app/api/generated`; запускай `pnpm generate:api`, когда меняется backend OpenAPI.
- Не редактируй файлы в `src/app/api/generated` вручную. Исправляй источник контракта в backend DTO/OpenAPI metadata и генерируй клиент повторно.

## Языки и локализация

- Использую английский для всего UI (меню, кнопки, текты)
