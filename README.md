# Video Quality Analyzer

**Предварительная проверка видео по техническим требованиям.** Пользователь добавляет ссылку в веб-интерфейсе или отправляет её в Telegram. Сервис проверяет доступность и метаданные YouTube-видео до загрузки, запускает анализ в фоне и возвращает отчёт с вердиктом, измерениями и таймкодами проблемных участков.

Проект показывает, как разрабатывать такой сервис с помощью **OpenAI Codex** и проверять результат по исходным требованиям, тестам и истории изменений.

## Что умеет сервис

- **Проверять видео до скачивания.** Предварительная проверка учитывает длительность, доступность, признаки YouTube Shorts и разрешение доступных форматов. При подтверждённом нарушении сервис прекращает обработку до загрузки медиа.
- **Анализировать скачанный файл.** Сервис проверяет разрешение и звуковую дорожку, ищет длительную тишину, перегрузку звука, частые склейки, чёрные экраны и зависания. Отчёт показывает, какие проверки пройдены и где стоит посмотреть фрагмент вручную.
- **Работать по профилям.** Администратор настраивает пороги и профиль по умолчанию. Профили версионируются, а отчёт хранит снимок критериев, по которым получен результат.
- **Обрабатывать видео через веб и Telegram.** Веб-интерфейс поддерживает массовый запуск анализа. В Telegram пользователь получает краткую сводку и полный TXT-отчёт в ответ на исходное сообщение.

## Как разрабатывался проект с ИИ

Инженер формулировал требования, принимал архитектурные решения и отвечал за качество результата. Codex работал с репозиторием как агент разработки: изучал существующий код, реализовывал задачи, добавлял тесты и исправлял найденные проблемы.

1. **Постановка.** В задаче фиксировались ожидаемое поведение, ограничения и сценарии проверки.
2. **Реализация.** Codex вносил изменения в код, миграции и документацию по постановке задачи.
3. **Инженерное ревью.** Проверялись архитектура, API-контракты, типизация и поведение в пограничных случаях.
4. **Проверка.** Сборка, проверка типов и тесты помогали выявить ошибки до фиксации результата.
5. **Фиксация.** Номер задачи в истории Git позволяет перейти от постановки к изменениям и тестам.

## Локальный запуск

Понадобятся Node.js `^20.19.0 || ^22.12.0 || ^24.0.0`, pnpm `10.12.1`, Docker с Compose и доступные в `PATH` команды `yt-dlp`, `ffmpeg` и `ffprobe`.

```bash
cp -n .env.example .env
pnpm install
pnpm infra:up
pnpm db:migrate
```

Запустите backend и frontend в отдельных терминалах.

```bash
pnpm dev:backend
pnpm dev:frontend
```

Откройте [веб-интерфейс](http://localhost:4200) или [Swagger](http://localhost:3000/api/docs). На пустой базе создаётся администратор `admin` с временным паролем `admin`. Приложение потребует сменить пароль при первом входе.

При развёртывании используйте HTTPS и проксируйте `/api` на NestJS с того же origin, что и веб-интерфейс. Укажите адрес приложения в `FRONTEND_ORIGIN`.

### Подключение Telegram

1. Получите токен у [@BotFather](https://t.me/BotFather), укажите его в `TELEGRAM_BOT_TOKEN` в локальном `.env` и перезапустите backend. При пустом токене Telegram отключён.
2. Отправьте боту `/id`. В разделе «Пользователи» администратор привязывает полученный Telegram ID к аккаунту.
3. В личном чате отправьте YouTube-ссылку или `/analyze <код-профиля> <ссылка>`. Команда `/profiles` покажет активные профили, а `/lang` позволит выбрать язык.

Бот получает сообщения через long polling. Ему нужен исходящий доступ к `api.telegram.org`. Если ранее для бота был настроен webhook, снимите его перед запуском.
